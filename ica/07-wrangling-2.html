🧩 Learning Goals

By the end of this lesson, you should be able to:

  • Manipulate and explore strings using the stringr package
  • Construct regular expressions to find patterns in strings

Motivation

In 2018 the data journalism organization The Pudding featured a story called 30 Years of American Anxieties highlighting themes in 30 years of posts to the Dear Abby column (an American advice column).

To understand themes in text data, one can conduct a qualitative text analysis which is a manual process that involved multiple people reading through the instances of text several time until they reach a consensus about themes. Given the amount of labor involved, this process is suitable for medium datasets.

For large datasets, one might want to use quantitative & computational text analysis which leverages computers, data science techniques, and natural language process to extract themes from the data. We will explore this approach in this lesson.

Both qualitative and computational approaches can be used in tandem. Often, using computational tools can help focus a close reading of select texts, which parallels the spirit of a qualitative analysis.

To prepare ourselves for a computational analysis, let’s learn about strings.

Strings

Strings are objects of the character class (abbreviated as <chr> in tibbles).

When you print out strings, they display with double quotes:

Code
some_string <- "banana"
some_string
[1] "banana"

Working with strings generally will involve the use of regular expressions, a tool for finding patterns in strings.

Regular expressions (regex, for short) look like the following:

"^the" <-- Find strings that start with "the"
"end$" <-- Find strings that end with "end"

Before getting to regular expressions, let’s go over some fundamentals about working with strings. The stringr package (which a package in the tidyverse ecosystem) is great for working with strings.

Code
library(tidyverse) # The stringr package is part of tidyverse

Escape Characters

Because " and ' are special characters in the creation of strings, R offers another way to put them inside a string. We can escape these special characters by putting a \ in front of them:

Code
string1 <- "This is a string with \"double quotes\""
string2 <- "This is a string with \'single quotes\'"
str_view(string1)
[1] │ This is a string with "double quotes"
Code
str_view(string2)
[1] │ This is a string with 'single quotes'

Given that \ is a special character, how can we put the \ character in strings? We have to escape it with \\.

Combine

Often we will want to create new strings within data frames. We can use str_c() or str_glue(), both of which are vectorized functions, ie, they take vectors as inputs and provide vectors as outputs which means that they can be used within mutate()

  • With str_c() the strings to be combined are all arguments separated by commas.
  • With str_glue() the desired string is written as a template with variable names inside curly braces {}.
Code
df <- tibble(
    first_name = c("Arya", "Olenna", "Tyrion", "Melisandre"),
    last_name = c("Stark", "Tyrell", "Lannister", NA)
)
df
# A tibble: 4 × 2
  first_name last_name
  <chr>      <chr>    
1 Arya       Stark    
2 Olenna     Tyrell   
3 Tyrion     Lannister
4 Melisandre <NA>
Code
df |>
    mutate(
        full_name1 = str_c(first_name, " ", last_name),
        full_name2 = str_glue("{first_name} {last_name}")
    )
# A tibble: 4 × 4
  first_name last_name full_name1       full_name2      
  <chr>      <chr>     <chr>            <glue>          
1 Arya       Stark     Arya Stark       Arya Stark      
2 Olenna     Tyrell    Olenna Tyrell    Olenna Tyrell   
3 Tyrion     Lannister Tyrion Lannister Tyrion Lannister
4 Melisandre <NA>      <NA>             Melisandre NA

Substring

The str_sub() function gets a substring of a string. The 2nd and 3rd arguments indicate the beginning and ending position to extract.

  • Negative positions indicate the position from the end of the word, eg, -3 indicates “3rd letter from the end”
  • Specifying a position that goes beyond the word won’t result in an error. str_sub() will just go as far as possible.
Code
x <- c("Apple", "Banana", "Pear")
x
[1] "Apple"  "Banana" "Pear"
Code
str_sub(x, start = 1, end = 3)
[1] "App" "Ban" "Pea"
Code
str_sub(x, start = -3, end = -1)
[1] "ple" "ana" "ear"
Code
str_sub(x, start = 2, end = -1)
[1] "pple"  "anana" "ear"
Code
str_sub("a", start = 1, end = 15)
[1] "a"

Quantifiers

  • Letters and numbers in a regex are matched exactly and are called literal characters.
  • Most punctuation characters, like ., +, *, [, ], and ?, have special meanings and are called metacharacters.
  • Quantifiers are metacharacters that specify how many times the proceeding character (group or character class) must occurs for a match to be found:
    • ?: the proceeding character must occurs 0 or 1 times for a match to be found
    • +: the proceeding character must occurs 1+ (1 or more times) for a match to be found
    • *: the proceeding character must occurs 0+ (0 or more times) for a match to be found

Character Classes

  • We can match any of a set of characters with [] (called a character class), e.g., [abcd] matches “a”, “b”, “c”, or “d”.
  • We can invert the match by starting with ^: [^abcd] matches anything except “a”, “b”, “c”, or “d”.
Code
# Match words that have vowel-x-vowel

Anchors & Groups

  • The ^ operator indicates the beginning of a string, and the $ operator indicates the end of a string, eg, ^a matches strings that start with “a”, and a$ matches words that end with “a”.
  • Parentheses group together parts of a regular expression that should be taken as a bundle. Much like parentheses in arithmetic statements, eg, ab+ is a little confusing. Does it match “ab” one or more times? Or does it match “a” first, then just “b” one or more times? (The latter, as we saw in an earlier example.) We can be very explicit and use a(b)+.

Regex Functions

The following are core stringr functions that use regular expressions:

  • str_view() - View the first occurrence in a string that matches the regex
  • str_count() - Count the number of times a regex matches within a string
  • str_detect() - Determine if (TRUE/FALSE) the regex is found within string
  • str_subset() - Return subset of strings that match the regex
  • str_extract(), str_extract_all() - Return portion of each string that matches the regex. str_extract() extracts the first instance of the match. str_extract_all() extracts all matches.
  • str_replace(), str_replace_all() - Replace portion of string that matches the regex with something else. str_replace() replaces the first instance of the match. str_replace_all() replaces all instances of the match.
  • str_remove(), str_remove_all() - Removes the portion of the string that matches the pattern. Equivalent to str_replace(x, "THE REGEX PATTERN", "")

## 🧩 Learning Goals

By the end of this lesson, you should be able to:

- Manipulate and explore strings using the `stringr` package
- Construct regular expressions to find patterns in strings


## Motivation

In 2018 the data journalism organization [The Pudding](https://pudding.cool/) featured a story called [30 Years of American Anxieties](https://pudding.cool/2018/11/dearabby/) highlighting themes in 30 years of posts to the Dear Abby column (an American advice column).

To understand themes in text data, one can conduct a **qualitative text analysis** which is a manual process that involved multiple people reading through the instances of text several time until they reach a consensus about themes.  Given the amount of labor involved, this process is suitable for medium datasets.

For large datasets, one might want to use **quantitative & computational text analysis** which leverages computers, data science techniques, and natural language process to extract themes from the data.  We will explore this approach in this lesson.

Both qualitative and computational approaches can be used in tandem. Often, using computational tools can help focus a close reading of select texts, which parallels the spirit of a qualitative analysis.

To prepare ourselves for a computational analysis, let's learn about strings.


## Strings

Strings are objects of the `character` class (abbreviated as `<chr>` in tibbles).

When you print out strings, they display with double quotes:

```{r chr_class}
some_string <- "banana"
some_string
```

Working with strings generally will involve the use of **regular expressions**, a tool for finding patterns in strings.

Regular expressions (regex, for short) look like the following:

```
"^the" <-- Find strings that start with "the"
"end$" <-- Find strings that end with "end"
```

Before getting to regular expressions, let's go over some fundamentals about working with strings. The `stringr` package (which a package in the `tidyverse` ecosystem) is great for working with strings.

```{r doc_setup_07}
#| message: false

library(tidyverse) # The stringr package is part of tidyverse
```

### Combine

Often we will want to create new strings within data frames. We can use `str_c()` or `str_glue()`, both of which are vectorized functions, ie, they take vectors as inputs and provide vectors as outputs which means that they can be used within `mutate()`

- With `str_c()` the strings to be combined are all arguments separated by commas.
- With `str_glue()` the desired string is written as a template with variable names inside curly braces `{}`.

```{r str_c_glue}
df <- tibble(
    first_name = c("Arya", "Olenna", "Tyrion", "Melisandre"),
    last_name = c("Stark", "Tyrell", "Lannister", NA)
)
df
```

```{r}
df |>
    mutate(
        full_name1 = str_c(first_name, " ", last_name),
        full_name2 = str_glue("{first_name} {last_name}")
    )
```

### Substring

The `str_sub()` function gets a substring of a string. The 2nd and 3rd arguments indicate the beginning and ending position to extract.

- Negative positions indicate the position from the end of the word, eg, -3 indicates "3rd letter from the end"
- Specifying a position that goes beyond the word won't result in an error. `str_sub()` will just go as far as possible.

```{r str_sub}
x <- c("Apple", "Banana", "Pear")
x
```

```{r}
str_sub(x, start = 1, end = 3)
str_sub(x, start = -3, end = -1)
str_sub(x, start = 2, end = -1)
str_sub("a", start = 1, end = 15)
```

### Quantifiers

- Letters and numbers in a regex are matched exactly and are called **literal characters**.
- Most punctuation characters, like `.`, `+`, `*`, `[`, `]`, and `?`, have special meanings and are called **metacharacters**.
- **Quantifiers** are metacharacters that specify how many times the proceeding character (group or character class) must occurs for a match to be found:
    - `?`: the proceeding character must occurs 0 or 1 times for a match to be found
    - `+`: the proceeding character must occurs 1+ (1 or more times) for a match to be found
    - `*`: the proceeding character must occurs 0+ (0 or more times) for a match to be found


### ✏️ Predict Quantifier Matches

Before running the code below, predict what matches will be made. Run the code to check your guesses. Note that in all regex's below the `?`, `+`, `*` applies to the `b` only (not the `a`).

```{r ex_regex_quantifiers}
str_view(c("a", "ab", "abb"), "ab?")
```

```{r}
str_view(c("a", "ab", "abb"), "ab+")
```

```{r}
str_view(c("a", "ab", "abb"), "ab*")
```

### Character Classes

- We can match any of a set of characters with `[]` (called a **character class**), e.g., `[abcd]` matches "a", "b", "c", or "d".
- We can invert the match by starting with `^`: `[^abcd]` matches anything except "a", "b", "c", or "d".

```{r regex_classes}
# Match words that have vowel-x-vowel
str_view(words, "[aeiou]x[aeiou]")

# Match words that have not_vowel-y-not_vowel
str_view(words, "[^aeiou]y[^aeiou]")
```

### Anchors & Groups

- The `^` operator indicates the beginning of a string, and the `$` operator indicates the end of a string, eg, `^a` matches strings that start with "a", and `a$` matches words that end with "a".
- Parentheses group together parts of a regular expression that should be taken as a bundle. Much like parentheses in arithmetic statements, eg, `ab+` is a little confusing. Does it match "ab" one or more times? Or does it match "a" first, then just "b" one or more times? (The latter, as we saw in an earlier example.) We can be very explicit and use `a(b)+`.

### Regex Functions

The following are core `stringr` functions that use regular expressions:

- `str_view()` - View the first occurrence in a string that matches the regex
- `str_count()` - Count the number of times a regex matches within a string
- `str_detect()` - Determine if (TRUE/FALSE) the regex is found within string
- `str_subset()` - Return subset of strings that match the regex
- `str_extract(), str_extract_all()` - Return portion of each string that matches the regex. `str_extract()` extracts the first instance of the match. `str_extract_all()` extracts all matches.
- `str_replace(), str_replace_all()` - Replace portion of string that matches the regex with something else. `str_replace()` replaces the first instance of the match. `str_replace_all()` replaces all instances of the match.
- `str_remove(), str_remove_all()` - Removes the portion of the string that matches the pattern. Equivalent to `str_replace(x, "THE REGEX PATTERN", "")`


### ✏️ Search for Themes

Pick a theme from the article and use each of the functions above, starting with `str_count()`, to search for it in the `posts` data. Pull up each function's documentation page and read through the arguments as you go.

```{r}
marriage_pattern <- regex("marriage|married|marry", ignore_case = TRUE)

posts |>
    mutate(n_marriage = str_count(question_only, marriage_pattern)) |>
    summarize(total_mentions = sum(n_marriage, na.rm = TRUE), letters_with_theme = sum(n_marriage > 0, na.rm = TRUE))

posts |>
    mutate(has_marriage = str_detect(question_only, marriage_pattern)) |>
    count(has_marriage)

marriage_letters <- str_subset(posts$question_only, marriage_pattern)
head(marriage_letters)

str_view(head(marriage_letters, 10), marriage_pattern)

head(str_extract(marriage_letters, marriage_pattern))

head(str_extract_all(marriage_letters, marriage_pattern))

head(str_replace(marriage_letters,marriage_pattern,"[MARRIAGE]"))

head(str_replace_all(marriage_letters, marriage_pattern, "[MARRIAGE]"))

head(str_remove(marriage_letters, marriage_pattern))

head(str_remove_all(marriage_letters, marriage_pattern))
```
